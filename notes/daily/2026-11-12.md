# 2026-11-12 项目文件结构与各文件作用

今天梳理 data-quality-monitor 项目当前的完整文件结构，按目录分组记录每个文件的作用，方便日后回顾。

## 一、根目录的配置与说明文件

| 文件 | 作用 |
|------|------|
| `pyproject.toml` | 项目总配置：依赖（含可选依赖 dev/dm）、构建系统、命令入口 `dqm`、pytest 和 ruff 的工具配置，是安装/构建的单一事实来源 |
| `.gitignore` | 告诉 Git 哪些文件不纳入版本管理（.venv、缓存、*.db、egg-info 等） |
| `README.md` | 项目说明主页：功能、安装方式、使用示例 |
| `LICENSE` | 开源许可证 |
| `pandas操作详解.md` | pandas 学习文档（14 章），ruff 已排除不检查 |
| `pandas_walkthrough.py` | 配合 pandas 文档的 9 个操作演示脚本 |
| `数据开发转型计划-完整总结 (1).md` | 数据开发转型的规划与总结文档 |

## 二、core/ 核心代码（项目的"五脏六腑"）

| 文件 | 作用 |
|------|------|
| `__init__.py` | 把 core 目录标记为一个 Python 包，使其可被 import |
| `cli.py` | 命令行入口与"大脑"：解析参数、调度加载→校验→检查→报告全流程，定义退出码（0/1/2） |
| `config_loader.py` | 从 rules.yaml 读取规则，加载成 Python 字典结构 |
| `validator.py` | 规则配置的结构校验（schema 校验），在运行前把"配置写错"挡在最前面，fail-fast |
| `data_loader.py` | 数据加载器：从 CSV 或数据库（SQLAlchemy）读数据，统一成 DataFrame，下游不关心数据来源 |
| `checker.py` | 规则引擎：实现各条质量检查规则（not_null/unique/range/zscore/allowed_values/null_ratio/row_count） |
| `reporter.py` | 报告导出：把检查结果导出成 JSON 或 Markdown，支持单表和多表 |

## 三、config/ 配置文件

| 文件 | 作用 |
|------|------|
| `__init__.py` | 把 config 标记为 Python 包 |
| `rules.yaml` | 核心规则定义：TableA、TableB 的列级和表级检查规则 |
| `tables.txt` | 表名清单（TableA、TableB），供 `--tables-file` 参数读取 |
| `data_list.txt` | CSV 路径清单，供 `--data-file` 参数读取；相对路径须在项目根运行 |

## 四、data/ 测试数据

| 文件 | 作用 |
|------|------|
| `TableA.csv` | 正常数据：6 条规则全过，退出码 0 |
| `TableA_bad.csv` | 坏数据：5 条 FAIL，用于验证失败场景 |
| `TableA_empty.csv` | 空表数据：row_count 失败，用于验证空表场景 |
| `TableB.csv` | 含 z-score 离群点的数据，用于验证异常检测 |
| `demo.db` | SQLite 演示数据库（由脚本生成，`.gitignore` 忽略，不提交） |

## 六、scripts/ 辅助脚本

| 文件 | 作用 |

## 十、自动生成、不提交的目录（.gitignore 忽略）

| 目录/文件 | 说明 |
|-----------|------|
| `.venv/` | 虚拟环境，含 Python、pytest、ruff、dqm 等可执行文件 |
| `.pytest_cache/` | pytest 运行缓存 |
| `.ruff_cache/` | ruff 检查缓存 |
| `__pycache__/` | Python 字节码缓存（各包目录下都可能有） |
| `*.egg-info/` | 打包安装时生成的元信息（含 entry_points.txt） |
| `data/demo.db` | 由 build_demo_db.py 生成的 SQLite 文件，*.db 被忽略 |

## 一句话总结数据流

`rules.yaml`（规则）→ `config_loader` 加载 → `validator` 校验 → `data_loader` 把数据读成 DataFrame → `checker` 执行检查 → `reporter` 导出报告；`cli.py` 负责把这条链路串起来，`ci.yml` 保证每次提交都自动验证，`tests/` 用 114 个测试守住质量。
