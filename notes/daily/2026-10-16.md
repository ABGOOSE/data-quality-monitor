2，改完test_checker之后，马上测试
    看输出 —— 四种方式都能用。解释一下怎么读结果：
        | 符号 | 意思 |
        | --- | --- |
        | `.` | 一个测试通过 |
        | `F` | 断言失败（结果和预期不符） |
        | `E` | 代码出错（抛了异常） |
        ```
    61 passed in 0.90s      # 全部通过 ✅
    5 passed, 56 deselected # 过滤后只跑 5 个，跳过 56 个
    38 passed               # test_checker.py 里正好 38 个测试函数
    ```
    写完测试**先别急着高兴**—— 有个隐藏风险：测试可能 "碰巧通过"（比如断言写错，恒为真）。验证方法：**故意把断言改错，看它红不红**。
    ```
    # 把正确断言
        assert result["null_ratio"] == 0.2
    # 故意改成错的
        assert result["null_ratio"] == 0.99   # ← 跑一下，必须红！
    ```
    - 红了 → 证明测试**真的能抓问题** ✅ → 改回正确值
    - 不红 → 你的测试形同虚设，断言写错了 ❌

    **这是 "测试有效性" 验证 ——TDD 的隐藏步骤**。红一次，你才敢信这个测试。
    ## 失败时的标准调试流程
    ```
        pytest -q                # 红：看到 F
        pytest -k null_ratio     # 缩小范围：哪个规则组坏了
        pytest tests/test_checker.py::test_xxx -q   # 精确到单个：只看它
    # → 修代码 → 再跑 → 绿
    ```
