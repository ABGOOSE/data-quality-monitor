# 首次接触pyproject.toml 
    1，同一份配置，pip / pytest / ruff 各自认领自己那一段
    2，TOML 是一种配置文件格式，特点就是「给机器读的，但人看着也像随手写的」——`[节名]` 分组 + `键 = 值`，比 YAML 更严格（不会缩进出错），比 JSON 更能写注释
    3，[project]
    项目的身份证，给 pip 和构建工具看
    4，[project.optional-dependencies]
    开发依赖：只有写代码的人需要（pytest 测试、ruff 检查），上线部署不装
    5，[tool.ruff]   ruff 的配置区
    [tool.XXX] 是通用约定 ——**任何工具都能在这个文件里拥有自己的小节
    6，[tool.pytest.ini_options]
    pytest 配置：去哪找测试（tests/）、去哪找代码（项目根）
📄 pyproject.toml 结构
固定 [project] ← PEP 621 标准规定，pip 硬编码识别
    固定 name / version / description / requires-python / dependencies ← 标准规定的键名
固定 [project.optional-dependencies] ← 标准规定的表名
    可改 dev ← 分组名自定义，改成 test / docs / all 都行
固定 [tool.ruff] ← 必须是工具真名，ruff 只认 [tool.ruff]
    固定 line-length / target-version ← ruff 文档规定的键名
固定 [tool.pytest.ini_options] ← pytest 规定的小节名
    固定 testpaths / pythonpath ← pytest 规定的键名
