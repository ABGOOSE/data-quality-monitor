1, 了解到多表yaml复用
    业内事实：成熟工具用 "专门机制"，不是锚点
    工具	            复用方式	                        官方态度
    GitLab CI	        extends（继承）	                    官方明确：" 比锚点更灵活可读，尽量用 extends"
    Soda（数据质量）	 for each dataset	                一组规则批量应用到多个表
    GitHub Actions	    workflow_call / composite action   复用整个工作流
    Kubernetes	        Kustomize / Helm	               不用锚点

2， 数据质量领域重点看 Soda：for each dataset
            # 概念示意（Soda 语法）
            for each dataset T:
            datasets:
                - TableA
                - TableB
                - TableC
            checks:
                - row_count > 0
                - duplicate_count(id) = 0
    *这组检查会自动跑在列出的每个表上—— 本质是 "规则是一整块，应用对象是多表"，
    比锚点更强大（能批量、能配通配符、能按表动态匹配列）。

3， soda缺陷，当列名不一致时候，不可以复用规则

4，解决： 列名不一致，使用同一套规则
    "模板 + 列名映射**"——YAML 锚点做不到（锚点会原样复制列名），必须写一小段渲染代码。

    业内做法：
        工具	        实现方式
        dbt	            generic test 定义成 {% test not_null(model, column_name) %}——列名是参数，在不同模型配置不同列名
        AWS Glue	    用 KEY_COLUMN_MAPPINGS，列名不同时写 source_col -> target_col
        CSV 校验工具	 header alias（列名别名 / 映射表）
    **dbt 的本质**：generic test 就是一个 "函数"，`column_name` 是参数，调用时传不同列名 —— 和你刚看到的演示一模一样。
